# 2026-10-30

## 上游同步：go-emby2openlist 正式 merge upstream v2.9.0

### 起因
GitHub 提示 `12 commits ahead of and 16 commits behind AmbitiousJun/go-emby2openlist:main`。
排查发现**并非缺功能**，而是 git 血缘断链。

### 根因
- 旧的 `76e94f7 合并上游 v2.9.0 改动并适配 Jellyfin` 是**手动搬代码**，`parents=f084280` 只有一个父提交
- 真正的 merge 提交必须有两个 parent，git 才能识别上游提交已"进来"
- 手动复制 / cherry-pick 后改写，git 一律看不到血缘 → 永远显示 behind

### 格式决策
`gofmt -l internal/` 报 6 个上游文件有多余连续空行（cors.go、media.go、playbackinfo.go、
localtree/should_keep_file_test.go、web/handler.go、web/route.go）。
**选择不动**：这些是上游代码遗留格式，格式化后下次 merge 上游会产生无谓冲突。

### 结果

- `go build ./...` 通过

- 回滚点：tag `backup/main-before-upstream-merge-20261030`（= 02df47f）

### 经验
- **同步上游必须用 `git merge upstream/main`，绝不能手动搬代码**，否则 GitHub 的
  ahead/behind 永远失真，且下次同步必然大冲突
- 强推前先 `git ls-remote --heads origin` 确认远端真实指向，不要凭本地 tracking 推断
